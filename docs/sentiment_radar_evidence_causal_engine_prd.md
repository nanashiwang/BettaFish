# A 股舆情雷达：证据归因引擎 PRD

## 1. 背景

当前雷达已经能告诉用户“哪个主题热、哪个板块弱、哪些个股异动”，但用户真正需要的是：这次异动背后正在交易什么逻辑，以及这个逻辑是否有真实来源支撑。

因此，今日预判卡需要从“状态卡”升级为“状态 + 原因 + 证据 + 反证”的证据归因卡。

## 2. 核心原则

1. 无来源不归因：没有新闻、政策、公告、行情或产业数据，不输出明确原因。
2. 来源可追溯：每条“为什么动”必须绑定真实来源、标题、URL 或行情证据。
3. 事实与推断分离：事实是来源说了什么；推断是可能影响哪个产业链；验证是市场是否已经反应。
4. 传闻不单独成因：社媒和论坛只能作为热度辅助，不能单独构成上涨原因。
5. 必须展示反证：公司澄清、旧消息重复、业务占比低、板块不扩散，都要作为风险边界。

## 3. 用户端展示

### 3.1 今日预判卡新增“为什么动”

卡片内展示：

- 一句话归因：基于真实来源的原因摘要；证据不足时明确写“疑似驱动”。
- 可信度：中等偏高 / 中等 / 证据不足。
- 证据数量：统计可追溯来源数量。
- 主来源：显示最重要的新闻/政策/公告来源。

### 3.2 证据抽屉新增“证据归因”

抽屉内展示：

- 为什么动：完整归因摘要。
- 驱动链路：真实事件 → 产业映射 → 行情验证 → 个股映射/反证提醒。
- 真实来源依据：来源、标题、URL、类型、可信度、采用原因。
- 反证提醒：哪些情况会推翻当前归因。
- 原有证据链、时间线、个股观察池继续保留。

## 4. 后台数据结构

当前第一版不新增数据库列，直接扩展 `radar_predictions.detail` JSONB：

```json
{
  "causal_summary": "为什么动的一句话证据归因",
  "confidence": "中等偏高/中等/证据不足",
  "causal_chain": [
    {"step": "真实事件", "text": "引用真实来源"},
    {"step": "产业映射", "text": "事件如何映射到真实板块"},
    {"step": "行情验证", "text": "热度z、价格z、量比、个股证据"},
    {"step": "反证提醒", "text": "需要继续观察的证伪条件"}
  ],
  "evidence_basis": [
    {
      "source": "来源名",
      "title": "真实标题",
      "url": "原始URL",
      "type": "新闻报道/政策监管/公司公告/行情验证/产业数据",
      "credibility": "高/较高/中/中低",
      "note": "为什么采用"
    }
  ],
  "counter_evidence": ["反证或失效条件"]
}
```

## 5. 管线规则

1. `news_collector` 采集真实新闻标题、来源、URL。
2. `topic_extractor` 聚合话题并记录 `news_indexes`。
3. `signals` 计算热度与行情背离。
4. `card_generator` 生成卡片时，只允许引用 `news_indexes` 指向的真实来源。
5. 如果 LLM 输出了不存在的来源标题，后端会过滤，并回退到真实来源列表。
6. 旧版历史卡未保存逐条标题时，前端明确提示“历史卡需重跑管线补齐完整归因”，不伪造来源。

## 6. 后续增强

- 增加 `evidence_documents` 表：保存完整新闻/政策/公告正文与快照。
- 增加 `market_events` 表：事件抽取，如出口限制、涨价、补贴、制裁、订单、事故。
- 增加 `industry_chain_map` 表：事件 → 产业链节点 → 板块 → 个股。
- 增加 `event_verification` 表：3/5 日后复盘该归因是否有效。
- 增加“证据等级”筛选：政策原文 > 公司公告 > 权威新闻 > 行业数据 > 社媒热度。

## 7. 合规边界

所有输出保持“舆情观察”，不提供买卖、仓位、目标价、收益承诺。归因只说明市场可能正在交易的逻辑与证据，不构成投资建议。
